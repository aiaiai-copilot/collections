# Проверить реализуемость линейного порядка с равноценностью

Type: prototype
Status: resolved

## Question

Может ли исполняемая линейная модель устойчиво поддержать отношения `A > B`, `A < B`, `A = B`, частичную определённость, проекции на пересекающиеся срезы и явный пересмотр противоречащих решений?

## Confirmed constraints

- Проверяется чистый модуль без UI, production-хранилища, сервера, синхронизации и конкурентного редактирования.
- Модель представляет частичный или полный порядок групп общего места; неизвестное отношение не означает равноценность, а равноценность сохраняется явно.
- Приоритеты остаются линейной моделью одного критерия. DAG, зависимости задач, универсальный графовый интерфейс и гипотетические адаптеры не реализуются.
- Объект принадлежит не более чем одному общему месту; строгий порядок мест транзитивен и не содержит циклов.
- Пересекающиеся срезы сохраняют одинаковый относительный порядок общих объектов, а срез завершён только когда каждая его пара строго упорядочена или явно равноценна.
- Противоречивый пересмотр должен быть отклонён с объяснением либо атомарно создать новый корректный порядок по явной политике; действующий порядок нельзя повредить молча.
- Тесты проверяют интерфейс модуля, включая `A = B`, `B = C`, затем `A > C`, а также смысл перетаскивания одного объекта из общего места.

## Out of scope

- UI и изменения HTML-прототипов.
- Реализация DAG или универсального графового ядра.
- Новые версии объектов сверх минимума, необходимого для проверки текущей линейной модели.

## Answer

Да. Исполняемый модуль [`linear-order.PROTOTYPE.mjs`](../../../prototypes/linear-order.PROTOTYPE.mjs) через единый публичный интерфейс `record`, `revise` и `project` устойчиво поддерживает частичный порядок групп общего места без отдельного универсального графового слоя.

Источником истины служат активные пользовательские решения. Проекция заново выводит группы общего места, все транзитивные строгие отношения, неизвестные пары и полноту произвольного среза. Противоречащее решение отклоняется без изменения действующего порядка и возвращает вид конфликта вместе с идентификаторами решений, из которых следует противоречие.

Обычная запись не может молча заменить существующее отношение, но пользователь может передумать через явный пересмотр. Пересмотр атомарно отзывает только явно перечисленные решения, проверяет новое решение поверх оставшихся и заменяет действующее состояние лишь при успехе. В простых случаях `A = B → A > B` и `A > B → A = B` достаточно отозвать прежнее решение пары и добавить новое. Для транзитивно выведенного отношения требуется отозвать достаточно решений, чтобы между объектами не осталось другого пути прежней равноценности или строгого порядка; остальные отношения сохраняются. Если перечисленных отзывов недостаточно, пересмотр отклоняется и прежний порядок остаётся без изменений.

Четырнадцать локальных модульных тестов в [`linear-order.PROTOTYPE.test.mjs`](../../../prototypes/linear-order.PROTOTYPE.test.mjs) проверяют исходы `A > B`, `A < B`, `A = B`, транзитивность, циклы, пересекающиеся полные и неполные срезы, объяснимые конфликты, сценарий `A = B`, `B = C`, затем `A > C`, обе замены `A = B → A > B` и `A > B → A = B`, а также успешный и отклонённый пересмотр транзитивных отношений.
