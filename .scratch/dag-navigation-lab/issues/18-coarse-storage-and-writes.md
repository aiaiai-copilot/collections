# Оценить локальное хранилище и изменения в ограниченном бюджете

Type: task
Status: resolved
Blocked by: 17

## Question

Какую грубую область чтения и изменений подтверждает один реальный
изолированный источник при сохранении полного согласованного ответа?

## Scope

[Бюджетный план](../../../docs/research/dag-navigator-applicability-budget.PLAN.md):
25 единиц, D1/D2. Один исследовательский кандидат PostgreSQL, не выбор
backend продукта. Wayfinder, codebase-design и TDD; актуальную документацию
механизмов проверить по первоисточникам перед реализацией.
Сначала проверить окружение, ресурсы и фактический target; установка/запуск
не выполнялись при планировании. Не использовать продуктовые .env/БД.
Non-local/production/неясная изоляция требуют разрешения пользователя.

Реализовать только необходимый адаптер/снимок/журнал изменений, сверить
полные ответы с эталоном. Один вариант согласования, без второго хранилища
или промышленного backend. Не терять затраты настройки и отладки из бюджета.
Этот адаптер и общий измерительный путь должны переиспользоваться в D1/D2
и C1/C2: новый профиль — конфигурация/данные/нагрузка, не новая версия стенда.
Построение и загрузку данных учитывать отдельно от времени чтения.

## Output

Фактические задержки, ресурсы, достигнутая запись, согласованность и
догоняющее обновление; либо точное описание того, что не удалось проверить
в бюджете. При отсутствии корректного адаптера не переходить к имитации
backend цифрами in-memory: сохранить пробел и пересмотреть следующий пакет.

## Подготовка — 2026-09-28

Задача claimed. [Паспорт подготовки](../../../docs/research/dag-navigator-storage-stage.PLAN.md):
локальный OrbStack доступен, работающих контейнеров нет, образ PostgreSQL
17.10 уже имеется; image ID/digest сохранены. Без скачивания/установки,
подключения к чужим БД или запуска сервера. Версия проверена одноразовым
изолированным контейнером, завершённым с `--rm`. Для Docker socket обычный
sandbox потребовал штатное разрешение; обходов не было.

Один disk-backed контейнер без сети/портов и один адаптер планируются для
D1/D2/C1/C2. Короткий согласованный снимок, атомарная ревизия пространства,
полный ответ без скрытого top-N. Исследовательский транспорт рассматривается
через постоянный `psql`, без subprocess на каждый SQL; его накладные расходы
не выдавать за чистое время БД. Границы ресурсов и проверка владения target
описаны в паспорте, перед интеграционным запуском проверить снова.

По TDD пользователю предложено подтвердить три внешних поведения тестов:
полный ответ против эталона; атомарные изменения/согласованный снимок;
отказ при посторонней БД. После этого пользователь ответил «Продолжай»;
продолжаем с предложенными границами. Нагрузка и D1/D2 не запускались.
Подготовка оценена в 3 единицы пакета, общий расход 34/100, остаток 66.
Следующий шаг после согласования — малый сквозной red→green, не новый
нагрузочный профиль и не безусловный запуск 100k.

## Answer

[D1](../../../docs/research/dag-navigator-storage-D1.md) и
[D2](../../../docs/research/dag-navigator-storage-D2.md) завершены на одном
исследовательском PostgreSQL-кандидате/подготовленном корпусе100k/1k/100/k10.
D2 не повторял load/индекс/D1: один эталон с поправками на три окна;
12/12 малых тестов,42 совпавших полных ответа, worker exit0 и журнал complete.
Весь восстановленный корпус и309 коммитов повторно сверены read-only.

Заданные100 одиночных изменений за10s подтверждены в каждом окне вместе
с одним смешанным reader1Hz; затем атомарная пачка21 записи и остановка.
Медианы одиночной записи4,67…6,75ms, свободного «Всего»941…985ms,
свободного10%-среза242…339ms. Долгое согласованное чтение могло отстать
от текущей БД до11 уже подтверждённых изменений. После остановки записи
запланированное чтение достигло итоговой ревизии через1,23…1,33s; это
включает ожидание следующего1s-такта, не проверка уведомлений/debounce/SLA.

Подтверждён этот короткий режим с небольшим рабочим набором изменений,
не предел записи/QPS, длительная стабильность или много читателей.
Практическая применимость требует сопоставить эти затраты со сценарием.
Рост отклика узкого свободного чтения между окнами причинно не изолирован;
новая диагностическая серия автоматически не назначается.

Контейнер остановлен exit0, volume/корпус/индекс сохранены; seq309, не0.
Следующий C1/C2 должен явно принять эту ревизию и восстановленные данные.
Никаких установок/чужих БД/повтора старых серий, коммитов или push.
Бюджет D2 +7, хранилище24/25, общий55/100, остаток45. Это экспертная
трудоёмкость, не доля пространства параметров. Следующий фронтир —
[конкуренция и разделение пространств](19-coarse-concurrency.md).
