# Свести грубую карту применимости в пределах бюджета

Type: task
Status: resolved
Blocked by: 17, 18, 19

## Question

Как измеренные характеристики и затраты соотносятся с реалистичными
сценариями применения, какие условия и существенные неизвестные должны
учитывать дальнейшие решения? Применимость не бинарна: подготовить основу
для последующей дифференциации по её классам, не смешивая их со степенью
подтверждённости свидетельств. Классы и пороги ещё не утверждены.

## Scope

[Бюджетный план](../../../docs/research/dag-navigator-applicability-budget.PLAN.md):
защищённые 15 единиц. Wayfinder; не новый измерительный этап. Свести старые
и новые факты в `docs/research/dag-navigator-applicability-map.md`, не смешивать
разные профили/протоколы. Оценки ресурсов и передачи данных отделять от
замеров; не обещать SLA, выбранный backend, OpenAPI или мобильный предел.

При остановке по бюджету предыдущие этапы оформляют частичные отчёты и
явно передают пробелы, чтобы сводка не оставалась заблокированной бесконечно.
Если их обязательные проверки не завершены, снять зависимости для выпуска
частичного отчёта с объяснением, не объявляя те проверки успешными.

## Output

Карта по сценариям применения, подтверждающие профили, ресурсные условия,
степень уверенности, оставшиеся неизвестные и решения, которым они мешают.
Итоговый расход и точка остановки; дополнительное исследование — только
по отдельному решению, не автоматическое продолжение старой широкой шкалы.

## Answer

2026-10-03: подготовлена [частичная карта применимости](../../../docs/research/dag-navigator-applicability-map.md).
Она связывает параметры/форму данных, назначения тегов, ширину полного
ответа, чтения/изменения/конкуренцию и ресурсы с четырьмя семействами
сценариев. In-memory и PostgreSQL не объединены в одну шкалу; классы
применимости не назначены и не смешаны со свидетельствами. Нет выдуманного
процента охвата пространства, выбранного backend, API, SLA или cap данных.

Сохранены S1/C2 и другие существенные пробелы; у каждого — заблокированное
решение и минимальная адресная будущая проверка. Сетевые времена рассчитаны
с явными допущениями, не представлены измерениями телефона. Offline-сверка
16 основных JSONL/SHA/terminal type и ключевых медиан, прогрев исключён;
проверяемость/состав исторической миллионной серии записаны в карте.
Новых запусков/тестов/правок измеренного кода нет, БД не запускалась.

Итоговый экспертный расход85/100 (+15 защищённая сводка), остаток15
сохранён, не расходуется автоматически. Ограниченный этап завершён
**частичным результатом**, не объявлением всей применимости исследованной.
Следующее решение — [«Определить классы применимости относительно требований сценариев»](21-define-applicability-classes.md).
Не начинать новые опыты или возвращаться к API до проверки зависимостей
конкретного решения от пробелов.
