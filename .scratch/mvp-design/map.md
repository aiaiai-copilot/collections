# Завершить проектирование MVP продукта

Label: wayfinder:map

## Destination

Завершённый проект ограниченной первой версии продукта, достаточный для
передачи исполнителю, который реализует её, проверит и доведёт до production.
Проектирование ведёт основной проектировщик в текущей сессии; передаётся
проект MVP целиком, а не отдельная незавершённая формализация DAG-контракта.
Проект готовится как [долговременная продуктовая основа для будущих исполнителей](../../docs/product/README.md#назначение-проектирования), а не одноразовое задание конкретной модели.

- **Подборки в теговом пространстве — 2026-10-19:** согласованы состав

  указывает действующее описание и оставшиеся вопросы. 2026-10-20
  [синхронизированы определения и границы навигации](issues/00-define-mvp-scope.md#синхронизация-предметных-определений--2026-10-20).
  [Вопрос о прямом изменении служебных тегов на верхнем уровне снят](issues/00-define-mvp-scope.md#граница-уровней-при-работе-со-служебными-тегами--2026-10-20):
  дополнительных ограничений операций не требуется.
  Подробные контракты и спецификации выпуска ещё требуют сверки;
  работа над основой продолжается, прежняя очередь MVP автоматически
  не возобновляется.

- **Новая основа 2026-10-18:** текущая работа — пересмотр терминологии
  и ментальной модели в ветке `codex/product-reframing`.
  [Пространства, коллекции и пользовательские срезы](issues/00-define-mvp-scope.md#пространства-коллекции-и-пользовательские-срезы--2026-10-18)

  базой и требуют проверки применимости к новой основе.

- **Маршрут изменён 2026-10-13:** пользователь разделил работу на проектирование
  и исполнение; после этого поручил продолжить и ответом «Принимается»
  подтвердил предложенное распределение и исключительный возврат
  обнаруженных противоречий. [Запись смены подхода](../dag-navigation-lab/issues/02-define-navigator-contract.md#проектирование-и-исполнение-разделены--2026-10-13).
- Проектирование, включая формализацию контрактов, остаётся здесь.
  Содержательные решения согласуются с пользователем; исполнитель получает
  завершённый пакет для реализации. Прежняя ранняя передача снята с очереди.
- Принятый общий критерий завершения проектирования: функции и границы MVP,
  пользовательские сценарии, модель данных, интерфейсы, ключевые технические
  решения и проверяемые условия выпуска определены достаточно, чтобы
  исполнитель не подменял их собственным проектированием продукта.
  Конкретные требования предстоит определить относительно выбранного MVP.
- MVP — ограничение состава первой версии, не разрешение отложить
  требования к сохранности данных и безопасной эксплуатации на неопределённое
  «потом». Конкретные требования и пороги ещё нужно согласовать.
- Это планирование, не разработка работающего MVP. Готовность проекта
  и доказанная готовность реализации к production — разные результаты.
- Для маршрута использовать `wayfinder`, `grilling`, `domain-modeling`
  и `codebase-design`; не более одного вопроса пользователю за сообщение.
  Общую неспецифичную логику заимствовать, описывая необходимые условия
  интеграции, а не заново проектируя её по частным случаям.
- Следствия согласованных правил фиксировать самостоятельно как пояснения
  и проверочные сценарии, без отдельного согласования каждого случая.
  На обсуждение выносить реальные продуктовые развилки, а не следствия
  определения. Пользователь прямо уточнил это на примере восстановления
  коллекции после более раннего удаления её элемента.
- Существующие решения переиспользуются после определения их применимости
  к этой версии. Альтернативные концепты не объединяются молча; старый
  выбор технического фундамента демонстрационного продукта не объявляется
  автоматически выбором для нового объёма MVP.
- Принят исключительный возврат обнаруженного при реализации противоречия:
  исполнитель фиксирует конкретный вопрос, а изменение проекта решается
  здесь. Это исключительное уточнение, не постоянная передача проектирования
  исполнителю. Свобода деталей реализации сохраняется в пределах проекта.
