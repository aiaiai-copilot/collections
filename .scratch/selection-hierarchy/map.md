# Иерархия подборок

Label: wayfinder:map

## Destination

Отдельный, свободный от деталей реализации концепт «Иерархия подборок», чья доменная модель достаточно точна для содержательного сравнения с действующим концептом коллекций по границам данных, навигации, поиска и общего порядка.

## Notes

- Это соседний bounded context, а не изменение действующей спецификации коллекций. Его канонический словарь находится в `../../docs/concepts/selection-hierarchy/CONTEXT.md`.
- Подтверждённая отправная точка: центральной сущностью является подборка с тег-фильтром, а отношение уточнения фильтров образует семантический DAG. Поверх него пользователь при необходимости может создать и редактировать необязательную пользовательскую иерархию подборок, выражающую его текущие предпочтения; фактический маршрут остаётся независимым от неё.
- Карта предназначена только для концептуальных решений. Проектирование базы данных, API, UI и реализация начинаются за пределами её destination.
- Для карты использовать `wayfinder`, для HITL-решений — `grilling` и `domain-modeling`. Пользователю задаётся не более одного вопроса за сообщение.
- После каждого разрешённого термина сразу обновлять только `../../docs/concepts/selection-hierarchy/CONTEXT.md`. Не переносить определения в корневой `../../CONTEXT.md` без отдельного решения о выборе концепта.
- За одну сессию разрешать не более одного ticket; ответ хранится в ticket, а здесь появляется только именованный context pointer.

## Decisions so far

- [Определить границу существования данных без коллекции](issues/00-define-existence-boundary.md): элементы, общий словарь тегов и глобальный поиск принадлежат единому личному пространству; корневые подборки не имеют более широких существующих подборок и не владеют элементами.
- [Определить наследование критериев и область порядка](issues/01-define-ordering-scope.md): явно назначенная сортируемая подборка наследует критерии всех более широких сортируемых подборок DAG, а каждый критерий несёт единый общий порядок, ограничиваемый составом конкретной подборки.
- [Различить совпадающие критерии разных родителей](issues/02-resolve-inherited-criterion-identity.md): одноимённые критерии объединяются после подтверждения общего смысла либо получают уточнённые имена; противоречивые порядки требуют явного разрешения до объединения.
- [Определить способы формирования подборки](issues/03-define-selection-membership.md): все подборки определяются фильтрами; ручного состава и ручных исключений из вычисляемого членства нет.
- [Определить выразительность фильтров](issues/04-define-filter-expressiveness.md): тег-фильтр является пересечением обязательных тегов без `OR` и `NOT`, а уточнение проверяется включением наборов тегов.
- [Определить жизненный цикл пользовательской иерархии подборок](issues/05-define-user-hierarchy-lifecycle.md): её связи выражают текущие предпочтения пользователя, не подменяют пользовательский маршрут и при несовместимости устраняются отдельными действиями в рекурсивном атомарном плане.
