# Демонстрационный продуктовый прототип «Коллекций»

Label: wayfinder:map

## Destination

Доступный по ссылке mobile-first web-продукт, в котором заранее приглашённый пользователь до начала работы входит одноразовым кодом из email, работает только со своими приватными коллекциями, а серверное хранение сохраняет и синхронизирует данные между его устройствами. Подтверждённое ядро прежнего интерактивного PoC реализовано как демонстрационный продуктовый прототип, пригодный для самостоятельного использования первыми лояльными пользователями и показа потенциальным инвесторам.

## Notes

- Текущий канонический deliverable — [черновик спецификации демонстрационного продуктового прототипа](issues/03-specify-demonstration-product.md). `ready-for-agent` у этого документа означает готовность к разбору пробелов; реализация ждёт явного утверждения spec и согласованных tracer-bullet tickets.
- Ticket «Выбрать технический фундамент демонстрационного продукта» разрешён промежуточным выбором Beget. Ticket «Собрать сохраняющий данные walking skeleton» создан до spec и `/to-tickets`; до переоценки не считать его готовым к реализации.
- Эта карта явно включает реализацию и развёртывание демонстрационного продукта, а не только планирование решений.
- `../../prototypes/collection-workspace.PROTOTYPE.html` служит поведенческой спецификацией подтверждённого ядра; монолитный HTML не переносится построчно и не становится production-кодом.
- Канонический словарь находится в `../../CONTEXT.md`; решения с участием пользователя обсуждаются по одному вопросу за сообщение.
- Для карты использовать `wayfinder`, для внешних фактов — `research`, для терминов — `domain-modeling`, для архитектурных швов — `codebase-design`, для UI-вопросов — `prototype`.
- На момент создания карты полноценного application-стека в репозитории нет: отсутствуют package manifest, lock-файл, app-конфигурация, backend и схема хранения.
- Пользователь входит до создания первой коллекции. Доступ разрешается только заранее приглашённым email; приглашения пока обслуживаются закрытым операторским инструментом, без административного интерфейса продукта.
- Данные разных пользователей изолированы. Общие пространства, совместное редактирование, роли и приглашения других участников не входят в этот этап.
- Интерфейс продукта не связывается напрямую с форматом хранения. Коллекции, элементы, подборки, теги/фильтры, поиск, хранение и сортировка образуют отдельные модули; authentication и persistence подключаются адаптерами через явные швы.
- Перед любым e2e или интеграционным тестом проверять фактический backend/API. Production, внешний или неизолированный стенд нельзя тестировать без явного предупреждения и разрешения пользователя.

## Decisions so far

- [Исследовать технический фундамент демонстрационного продукта](issues/00-research-product-foundation.md): исследование рекомендует для первого walking skeleton Next.js + Supabase + Vercel Pro с отдельным SMTP и server-side портами; Clerk + Neon остаётся жизнеспособным резервным вариантом.
- [Исследовать self-hosted VPS и Yandex Cloud как фундамент продукта](issues/04-research-self-hosted-yandex-foundation.md): PostgreSQL + NestJS + SPA жизнеспособен на своём VPS и в Yandex Cloud; варианты различаются операционной ответственностью, стоимостью Managed PostgreSQL и способом изоляции preview/test, а OpenAPI 3.1 остаётся spec-first Interface.
- [Выбрать технический фундамент демонстрационного продукта](issues/01-choose-product-foundation.md): промежуточно выбран один Beget VPS с PostgreSQL, NestJS и SPA; OpenAPI 3.1 и application Interfaces сохраняют независимость продукта от провайдера.

## Not yet specified

- После сохраняющего данные walking skeleton последовательно реализовать коллекции, элементы, автоматические и ручные подборки с «Без подборки», поиск и прямые ссылки, нижнюю навигацию, затем сортировку как отдельный модуль.
- Для выбранного Beget-фундамента ещё нужно определить границу первой демонстрационной готовности, цели диагностики и восстановления данных и достаточный объём автоматической проверки.
- Правила переноса или отказа от демонстрационных данных при последующем переходе к production-продукту определяются после появления фактической модели хранения.

## Out of scope

- Общие пространства, совместное редактирование, роли пользователей и пользовательский интерфейс управления приглашениями.
- Публичная самостоятельная регистрация без предварительного приглашения.
- Импорт, обмен коллекциями, премиальные и плагинные расширения, включая автоматические предложения тегов.
- Перенос монолитного HTML-прототипа как основы application-кода.
