# Исследовать технический фундамент демонстрационного продукта

Type: research
Status: resolved

## Question

Какие актуальные поддерживаемые web-стеки и управляемые платформы дают наименьший достаточно глубокий фундамент для mobile-first продукта с доступом только приглашённых email, входом одноразовым кодом, приватными данными каждого пользователя, серверным хранением, синхронизацией между устройствами и безопасным демонстрационным развёртыванием, если в репозитории пока нет application-стека?

Исследование должно опираться на первичные источники, сравнить не менее двух жизнеспособных вариантов и отдельно проверить стоимость и ограничения authentication, базы данных, миграций, локальной разработки, preview/test-окружения, deployment и возможности заменить конкретный адаптер хранения без переписывания продуктовых модулей.

## Answer

[Технический фундамент демонстрационного продукта «Коллекции»](../../../docs/research/product-prototype-foundation.md) сравнивает Next.js + Supabase + Vercel и Next.js + Clerk + Neon + Drizzle + Vercel по authentication, приватности данных, миграциям, локальному контуру, preview/test, deployment, стоимости и переносимости.

Для первого walking skeleton рекомендован Next.js + Supabase + Vercel Pro: это меньший цельный фундамент с полным локальным стеком, Postgres RLS и SQL migrations. Invite-only вход по коду строится через предварительное создание пользователя оператором, выключенный публичный signup и `shouldCreateUser: false`; для реальных пользователей обязательны отдельный SMTP и Supabase Pro. Clerk + Neon остаётся жизнеспособным резервом, если готовый authentication UX окажется важнее дополнительной операционной поверхности.
