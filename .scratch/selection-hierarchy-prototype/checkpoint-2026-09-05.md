## Что зафиксировано

Рабочий [HTML-прототип](../../prototypes/selection-hierarchy.PROTOTYPE.html) открывается локально с `?variant=A`. Он самодостаточен, без backend и постоянного хранилища. Варианты B/C сохранены как ранние альтернативы; пользователь выбрал для продолжения только A.

- Верхний уровень имеет заголовок «Мои подборки», логотип из карточек-плюсов слева и общий `＋` справа. На полностью пустом экране есть кнопка «Добавить».
- Общая форма открывается с `＋` верхнего уровня или любой подборки. По умолчанию выбран «Элемент»; переключатель «Подборка» меняет форму. Создание элемента и подборки работает в памяти.
- Элемент имеет название, текстовое содержимое и теги. Из списка открывается редактируемая детальная форма с сохранением; возврат ведёт в исходную подборку либо на верхний уровень. Поле содержимого присутствует и при создании.
- Подборка из другой подборки наследует её теги и требует хотя бы одного дополнительного тега. Дубликат нормализованного фильтра не создаётся: открывается существующая подборка с предупреждением.
- На верхнем уровне отображаются семантические корни. На экране подборки — её непосредственные семантические уточнения, без промежуточных транзитивных связей.
- Элементы показаны на уровне только тогда, когда не входят ни в одну из отображаемых подборок этого уровня. Счётчик подборки учитывает все соответствующие её фильтру элементы, включая покрытые уточнениями.
- Текущая корневая крошка называется **«Всё»** и ведёт на верхний уровень. «Личное пространство» отвергнуто пользователем как слишком длинное для mobile-first.
- Удалены видимые подписи «Все элементы личного пространства», «Уточняющие подборки» и «Фильтр подборки»; теги остаются видимыми. Отдельной кнопки «Добавить элемент» на экране подборки нет: используется общий `＋`.

## Доменные ограничения для навигации

Канонические определения находятся в словаре, ниже — ограничения, существенные для нового UI:

- Элементы независимы от подборок. Все подборки — AND-фильтры положительных тегов; ручного состава, `OR` и `NOT` нет.
- Один нормализованный набор тегов соответствует не более чем одной подборке. Для разных подборок отношение «шире → уже» означает строгое включение наборов тегов.
- Семантический DAG допускает нескольких родителей, несколько корней и произвольную глубину. Одна и та же подборка, доступная через разных родителей, остаётся одной сущностью.
- Неявный верхний уровень «Всё» находится вне DAG. Необязательная именованная подборка с пустым фильтром — отдельный узел; если она создана, это единственный семантический корень.
- Пользовательская иерархия — необязательные предпочтения поверх DAG; она не реализована в прототипе и не должна незаметно становиться единственным источником навигации.
- Текущий словарь связывает крошки и «назад» с фактическим маршрутом. Новая задача прямо допускает замену крошек; это не предрешает, как показывать связи и как возвращаться. Изменения терминов следует согласовать после выбора концепта.

## Ограничения текущей реализации

`selectionRouteIds` хранит одну цепочку переходов. `selectionBreadcrumbsMarkup`, `newEntryBreadcrumbsMarkup` и `elementBreadcrumbsMarkup` рисуют её на трёх экранах. `semanticPathToSelection` при отсутствии текущей цепочки выбирает первый найденный путь обходом DAG; это технический fallback, а не продуктовый выбор предпочтительного родителя.

Текущие крошки позволяют вернуться по показанному пути, но не раскрывают всех семантических родителей. Порядок создания узлов может повлиять на fallback-путь. Это следует явно проверять при сравнении новых концептов.

`syncVariantRoute` использует `history.replaceState`, добавляет `selection`, `path` и `element` в URL. Полноценной браузерной истории и восстановления состояния по URL нет. Это отступление прототипа от канонической ссылки по непрозрачному ID, а не подтверждённое продуктовое решение.

Данные живут только в JS-памяти текущей вкладки: перезагрузка, новая вкладка или новый worktree не восстанавливают созданные элементы и подборки. Git сохраняет код и документы, а не содержимое открытых вкладок. Визуальные примеры нужно заново собрать либо использовать отдельную явную тестовую фикстуру будущего эксперимента.

Поиск и настройки — заглушки. UI пользовательской иерархии, сортируемости и критериев ещё не разработан. Сейчас фиксируется рабочий эскиз, а не утверждение полноты реализации доменной модели.

## Сценарии для обсуждения новой навигации

Минимальный пример с несколькими родителями можно собрать с верхнего уровня через общую форму:

| Подборка | Фильтр |
| --- | --- |
| Фильмы | фильм |
| Спокойное | спокойное |
| Спокойные фильмы | фильм, спокойное |
| На вечер | фильм, спокойное, вечер |
| Вся медиатека — добавить позднее | пустой |

«Спокойные фильмы» доступны и из «Фильмы», и из «Спокойное». Добавление «Вся медиатека» меняет набор корней, но не идентичность остальных узлов. Элемент с тегами `фильм, спокойное, вечер` виден внутри «На вечер»; элемент без тегов сначала виден на верхнем уровне, а после появления пустого фильтра — внутри «Вся медиатека».

Сравнить способы: понять текущую подборку и доступные направления; выйти к любому более широкому контексту; вернуться по своему маршруту; попасть в «Всё»; открыть элемент и вернуться; создать уточнение в правильном контексте. Повторить с длинными названиями, глубоким маршрутом и несколькими родителями на узком мобильном экране. Состав и членство подборок при навигации не меняются. Конкретный вид UI выбирается в новой сессии вместе с пользователем.
