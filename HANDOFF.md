## Артефакт и запуск

Из текущего worktree:

```sh
python3 prototypes/serve-dag-navigation.PROTOTYPE.py
```

- Пустое начало: `http://127.0.0.1:8875/selection-hierarchy.PROTOTYPE.html?variant=A`.
- Явный пример: `http://127.0.0.1:8875/selection-hierarchy.PROTOTYPE.html?variant=A&fixture=dag`.
- Варианты A/B/C меняют только навигационную компоновку и переключаются нижними стрелками. Все используют основу исходного A.

Локальный сервер был запущен на `127.0.0.1:8875`. Если ссылка не открывается, запустить команду выше. Сервер раздаёт только каталог `prototypes`, backend/API отсутствует. ## На чём остановились

Пользователь согласовал смысл навигационного набора, пространства вверх/вниз, действий над тегами, релевантных элементов и одновременный показ выбранных тегов с облаком уточнений. «Облако выбранных тегов» было иллюстрацией симметрии, а не обязательным UI для переполнения. Детали находятся в текущем ticket и словаре.

A размещает выбранные теги сверху от облака, B — снизу, C — сбоку. Во время фильтрации экран занимает одна панель со счётчиком, выходом к результатам, фактическим возвратом и «Всё». Общая шапка приложения, добавление и нижняя навигация возвращаются при просмотре результатов. Все три компоновки подготовлены для реакции пользователя. Вопрос об обычном касании отправлен асинхронно; на момент записи ответа нет. Рабочий default — добавить/снять тег, соседняя ↗ переключает на один тег; настройка позволяет сравнить оба варианта.

Полноэкранный вариант появился по запросу пользователя после замечания о пустующей половине экрана. Высота облака теперь по умолчанию «По доступному месту»; фиксированные размеры доступны для ручного сравнения. Поддержаны вертикальный и горизонтальный экран; на ширине до 360 px боковой вариант переносит выбранные теги наверх. В примере «Фильмы на вечер» при 470×900 видны все 9 уточнений вместо прежних 4. При реальном переполнении «Ещё» раскрывает прокрутку внутри облака. Компоновки и проверки описаны в текущем ticket.

Привязка визуального веса, конкретное касание, обработка переполнения и некоторые переходы временного набора остаются гипотезами эскиза. Следующий шаг — интерактивная оценка и доработка по отзыву пользователя. Не закрывать ticket по факту наличия работающего HTML.

Последнее принятое решение: в уточнении показывать выбранные теги, облако, общий счётчик релевантных элементов и «Посмотреть результаты». Строки подборок/элементов и счётчик ближайших подборок на этом этапе не нужны; пользователь подтвердил это повторно, не открывать вопрос заново. «Продолжить фильтрацию» скрывает содержимое с сохранением тегов. Это реализовано во всех A/B/C; переключение не добавляет шаг в историю, возврат восстанавливает представление контекста. Рабочее начало нового контекста — уточнение, автоматического порога нет. В просмотре эскиз показывает компактные текущие теги, группированное содержимое и действие возврата к фильтрации; оценка этой компоновки ещё впереди. Подробности и проверки записаны в текущем ticket.
