# Десять пространств: перенос измерен, конкурентная серия частична

Дата:2026-10-03. [Паспорт до запуска](dag-navigator-concurrency-stage.PLAN.md),
[бюджет](dag-navigator-applicability-budget.PLAN.md),
[задача](../../.scratch/dag-navigation-lab/issues/19-coarse-concurrency.md#answer).
Это один ограниченный опыт на исследовательском кандидате, не бинарная
оценка применимости продукта и не SLA.

## Условия и разделение

Прежние100k элементов/100 подборок/1000 тегов/k10/seed23, seq618 после
[C1](dag-navigator-concurrency-C1.md). По числовому ID modulo10 десять
пространств получили по10k элементов/10 подборок. Общий объём не увеличен;
документы/теги/ID неизменны. SQL UPDATE в существующих таблицах/GIN, без
load/ANALYZE/перестройки/очистки кэшей/второго backend. Разделение логическое,
не десять физических индексов/таблиц/хостов. Новое только research control
для переноса/межпространственной пачки и маршрутизированное расписание;
измеренные файлы C1/D1/D2 byte-identical, интерфейс продукта не менялся.

Прежние2CPU/3GiB PostgreSQL17.10 ARM64, fsync/synchronous_commit on,
fuzzy limit0, SQL20/30/2/10s; worker768MiB/120s, фаза30s, owner256MiB,
volume10GiB. Фактический target проверен перед интеграционными запусками
и каждым connect: явный локальный socket, owned image/метка/volume,
network none, без портов/host mounts/продуктового DSN. Перед серией53%
memory free, примерно765GiB диска. Квоты после отказа не менялись.

План: один writer/четыре постоянных reader, три окна100 одиночных записей
и атомарная пачка21.48 основных чтений/окно прежних типов/1Hz, независимые
очереди, маршрут `(4*i+readerId)%10`. Отдельно4 baseline/10 probes на окно.
Десять disjoint эталонных индексов суммарно100k готовятся один раз, не
десять копий корпуса и не rebuild при записи. Ревизии/эталоны локальные.

| Профиль | Элементы / подборки | Словарь | Корни / пары строгого включения / максимальная цепь узлов |
| --- | --- | ---: | --- |
| Общий C1 |100k /100 |1000 |20 /143 /4 |
| C2, пространство00 |10k /10 |1000 |4 /12 /4 |
| C2, пространство01 |10k /10 |999 |4 /8 /3 |
| C2, каждое02…09 |10k /10 |999 |6 /6 /3 |

Глубина здесь — число вершин максимальной цепи строгого включения наборов
тегов; пары — все такие пары, не только непосредственные рёбра. Суммарно
68 локальных пар вместо143,75 связей исчезли. Контрольные теги0/1 имеют
1000/100 элементов в каждом пространстве, тег2 только в00; назначения
тегов100k/пространство,1m всего. Изменились локальные N/M/форма DAG и
маршруты: даже успешное сравнение не изолировало бы чистый эффект изоляции.

## Проверки и отказ

16/16 малых storage-тестов, exit0,6651,66ms. Новые проверки через ранее
согласованные seams source.read/snapshot и атомарной записи/восстановления:
полные локальные ответы, старый снимок при переносе, монотонная история
после merge, четыре маршрутизированные очереди, откат всей пачки при
SQL-ошибке. Это проверки корректности, не дополнительный нагрузочный масштаб.

Основной worker остановлен `step-timeout`, SIGKILL,33,79s от старта;
фаза `group-0/routed-readers-writes-verify-restore` заняла30,02s. До неё
завершились подготовка и перенос. **Завершённых окон и сохранённого набора
полных ответов основного масштаба нет.** Плановые186 сравнений не выполнены
как проверяемая серия. Медианы/очередь/catch-up, достигнутый темп записи и
сравнение отклика с C1 не установлены.

Фаза включает baseline, начальные журналы, расписание, probes, сверку и
восстановление. Буферы read/write сохранялись после окна; SIGKILL их лишил.
Нельзя локализовать задержку внутри фазы или назвать30s временем запроса.
SQL-отказ/OOM не зафиксирован; это не заменяет потерянную телеметрию.
diagnosing-bugs использован для границ разбора: точный симптом сохранён,
но воспроизведение/минимизация/исправление не выполнялись. Паспорт запрещает
автоматический повтор/изменение лимитов; корневая причина не установлена.

## Передача в сводку

Цена подготовки/переноса измерена, корректное разделение/восстановление
проверено. Конкурентный отклик десяти пространств — **пробел**. Из таймаута
не следует непригодность продукта, ухудшение/улучшение отклика или предел
пространств. Для будущего сравнения нужна адресная оценка цены/наблюдаемости
baseline, основного расписания и контроля, с сохранением частичных записей
до остановки. Только по отдельному решению, не оптимизация в этом пакете.

Порция +8 экспертных единиц, конкуренция15/15, общий70/100. Пересмотр рубежа70:
измерительный пакет заканчивается с пробелами S1/C2, далее защищённая сводка15.
Остаток30 =15 сводка +11 резерв +3 статический +1 storage; последние15 не
расходовать автоматически. R1–R4 использованы, R5 нет. Классы применимости
позднее определяются относительно требований сценария; измерено/оценено/
неизвестно — отдельная ось. Бюджет/число профилей не равны доле пространства.
