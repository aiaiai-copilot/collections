## Группировка результата

**Это схема данных результата, не структура директорий или файлов.**
Ветви обозначают логические группы сведений и поля. Уместность такого
уровня детализации [подтверждена пользователем](../../../.scratch/dag-navigation-lab/issues/02-define-navigator-contract.md#уровень-детализации-контракта-подтверждён--2026-10-08).
Группировка и приведённые имена полей приняты отдельно 2026-10-09.
Полная вложенность, физические типы и организация реализации этим
не фиксируются.

```text
result
├─ bundleId
├─ dag-navigation
│  ├─ position
│  ├─ mode
│  └─ transitions
└─ results
   ├─ total
   ├─ items
   └─ view
```

Дерево задаёт принятую группировку доступных сведений. Оно не требует
глубоких копий, повторного вычисления или вложенных JSON-объектов на проводе.
Успешный итог содержит `result`; детали его вложенных значений уточняются
отдельно без изменения принятых смыслов и гарантий.

| Поле | Содержание и гарантия | Ответственность |
| --- | --- | --- |
| `bundleId` | Непрозрачный идентификатор применённого комплекта, уникальный в пределах экземпляра координатора. Допускает сравнение на равенство; порядка и степени свежести не выражает | Общая координация |
| `dag-navigation.position` | Разрешённое положение: «Всё», сохранённая подборка или набор без совпадающей подборки; выбранные теги, их отображаемые названия, а у сохранённой подборки — ID и название | DAG-навигация |
| `dag-navigation.mode` | Режим, которому соответствуют навигационные сведения этого комплекта | DAG-навигация |
| `dag-navigation.transitions` | Полный логический набор готовых вариантов перехода для положения и режима, со сведениями для отображения, целями, количествами и связью с исходным выбором | DAG-навигация |
| `results.total` | Общее число уникальных элементов выбранного набора в этом комплекте, не размер страницы | Общая выдача по заданной выборке |
| `results.items` | Элементы полученной страницы в согласованном порядке | Общая выдача |
| `results.view` | Параметры, которым соответствует полученная страница: порядок, размер и описание места в выдаче | Общая выдача |

Разделение относится к смыслу данных, не размещению вычислений. Координатор
согласует результат, но не пересчитывает родителей или количества.
`results.total` — единственное место для общего количества:
заголовок навигации использует его, не независимую копию в `position`.
Количество у каждого варианта перехода относится к его целевому узлу
и остаётся в этом варианте. Оно не обязано совпадать с текущим `total`.

`dag-navigation` не включает межстраничные переходы и маршрут истории.
Написание с дефисом — принятое имя логического блока, не выбор языка
или синтаксиса доступа к полю в конкретном языке.

## Назначение метки

**Имя и описание приняты 2026-10-08:**
[запись согласования](../../../.scratch/dag-navigation-lab/issues/02-define-navigator-contract.md#имя-и-смысл-bundleid-приняты--2026-10-08).
Метка называется `bundleId` и идентифицирует конкретный применённый комплект.
Значение не булево; булев результат даёт сравнение двух идентификаторов.
Например, комплекты A, B и C различимы между собой, а флаг «изменился»
без указания исходного комплекта такого различия не выражает.
Физический тип и способ формирования идентификатора ещё не выбраны.

Метка позволяет приложению распознать, остался ли доступным тот же
применённый комплект или уже применён новый. Уведомление об ожидании
или ошибке фонового обновления не меняет метку сохранённого комплекта;
успешное применение нового комплекта меняет её. Сравнивать для этого
все элементы, переходы и количества не требуется.

Например, в выборке по-прежнему 6 элементов, но один заменён другим.
Теги и общее количество не различают старый и новый комплекты; метка
различает их применение. Она также позволяет соотнести сохранённый `result`
с доступным комплектом текущего состояния. Это не достаточная проверка
доступности действия: текущее намерение и его условия проверяются отдельно.

Приложение может не использовать метку, если ему не нужно различать
комплекты таким способом. Она не возлагает на него сборку или проверку
согласованности частей: это гарантирует модуль. Метка не является хешем
содержимого, доказательством свежести или ревизией всей базы. Разные метки
означают разные применения, но не обязательно различие каждого значения.
Её [правила и область сравнения](coherent-result-contract.DRAFT.md#метка-применённого-комплекта-в-публичном-состоянии)
сохранены; общая группировка результата также принята 2026-10-09.

## Предметная часть и выдача

`position` имеет уже принятые три смысловых варианта:

- **«Всё».** Пустой фильтр без идентичности именованной подборки.
- **Сохранённая подборка.** Фильтр, ID и название соответствующей подборки.
  Пустая именованная подборка сохраняет отличие от «Всё».
- **Набор без совпадающей подборки.** Непустой фильтр без придуманного ID
  подборки; для отображения используется выражение тегов.

Неизвестный фильтр ожидающего открытия по ID не является четвёртым вариантом
готового `position`: это намерение в текущем состоянии до готовности комплекта.
Идентичность тега отделена от отображаемого названия; физическое представление `TagRef`
и ID этой схемой не выбирается. Названия должны быть доступны для отображения,
но их дублирование рядом с каждым упоминанием тега не требуется.
Получение отображаемых названий через настроенный доступ
[принято отдельно](dag-navigator-data-access.DRAFT.md#получение-отображаемых-названий-тегов):
обычное приложение не обязано догружать их после получения комплекта.
Физическая форма связи ссылок с названиями этим не выбирается.

Варианты `transitions` сохраняют [принятый состав и правила](dag-navigator-upper-interface.DRAFT.md#представление-и-выбор-варианта-перехода):
соотношение фильтров, название/показанные
теги, полный фильтр целевого узла, количество его элементов и связь с исходным выбором.
Свободный режим не требует сохранённой подборки для каждого целевого узла.
Соотношение передаётся в поле `filterRelation` каждого варианта единого списка.
Связь с исходным выбором может быть общей для набора.
`bundleId` не подменяет эту связь: новый комплект при фоновом обновлении
не обязательно отменяет прежде показанный переход.

Параметры `view` описывают полученные данные, а не подставляются из нового
намерения пользователя. Точное представление места — номер, курсор или иной
способ — и политика его корректировки остаются в
[контракте выдачи](results-view-contract.DRAFT.md).
Схема не утверждает постоянный размер страницы, переход к произвольному
номеру или все ранее подготовленные предложения о пагинации. Структура
самого элемента также остаётся отдельным вопросом; `items` не означает
обязательную загрузку всех элементов или только их идентификаторов.

Для `items` сведены [данные элемента выдачи](results-view-contract.DRAFT.md#данные-элемента-выдачи):
состав для отображения по требованиям приложения без обязательного
копирования. Для сохранения места используется существующий ID элемента;
отдельный вопрос об идентичности снят как избыточный.
Для `view` предложены [поля order, pageSize, page](results-view-contract.DRAFT.md#предложение-поля-сведений-о-полученной-странице),
ещё не принятые. После сверки предметной части принят
[подход готовой основы просмотра](results-view-contract.DRAFT.md#готовая-основа-и-отличия-приложения):
состав уточняется через выбранное решение и отличия приложения, а не
путём отдельного проектирования каждого поля.
Логическая группировка результата не меняется.

## Сведения о текущем выборе

**Принято 2026-10-09 после пояснений:** [запись решения](../../../.scratch/dag-navigation-lab/issues/02-define-navigator-contract.md#сведения-о-текущем-выборе-приняты--2026-10-09).
`position` описывает любой текущий выбор: пользовательский узел,
промежуточный узел или «Всё». Речь о составе данных, не о внешнем виде UI.
В готовом результате это:

- `filter` — полный нормализованный AND-набор выбранных `TagRef`;
  присутствует всегда, в том числе как пустой набор.
- `selection` — ID (`id`) и название (`name`) сохранённой подборки,
  которой соответствует текущее положение. Если положение не является
  сохранённой подборкой, этих сведений нет.

`selection` означает сохранённую подборку; здесь это только её ID
и название, не список элементов. Для промежуточного узла достаточно
выбранного фильтра, искусственный ID подборки ему не создаётся.
Это сведения о подборке в данном положении, не полный объект источника:
её фильтр здесь совпадает с `filter` и второй раз не передаётся.
Имена `filter`, `id`, `name` приняты вместе с этим представлением;
имя `selection` уточнено 2026-10-12. Отсутствие `selection` не предписывает `null`, пропуск
поля или конкретный тип языка.

| Положение | `filter` | `selection` |
| --- | --- | --- |
| «Всё» | Пустой | Нет |
| Промежуточный узел | Непустой | Нет |
| Сохранённая подборка | Непустой | ID и название |
| Сохранённая подборка с пустым фильтром | Пустой | ID и название |

Соответствие подборке устанавливает Навигатор. Приложение не ищет её
по тегам и не трактует отсутствие `selection` как «сведения ещё грузятся»:
здесь описан уже готовый результат. При явном «Всё» `selection` отсутствует
даже при существовании именованной пустой подборки. Режим `free` сам по себе
также не означает отсутствия `selection`.

При изменении или удалении подборки новый комплект сохраняет выбранный
`filter`, а соответствие подборке определяет заново по принятым правилам.
Если фильтр недоступен, нового готового `position` не появляется: сохраняется
различие целостного результата и текущего состояния.

Отображаемые названия выбранных тегов остаются доступны в комплекте
по принятой гарантии; точная форма их связи с `TagRef` ещё не выбрана.
Количество находится в `results.total`, режим — в `dag-navigation.mode`.

Рассмотренная альтернатива — дополнительно передавать явный признак вида положения
(`all`, `node`, `temporary` в прежней смысловой записи). Он удобен для
прямого выбора ветви отображения, но дублирует различие, уже определяемое
пустотой фильтра и наличием подборки. Принят вариант без отдельного
признака; компромисс — потребитель различает три положения по двум полям.
Три принятых смысла при этом сохраняются; это не изменение правил навигации.

## Список вариантов перехода

**Принято 2026-10-10.** `dag-navigation.transitions`
передаётся как единый логический список. Каждый вариант
содержит поле `filterRelation`: соотношение фильтра целевого узла с исходным
фильтром, относительно которого выдан вариант. Все значения определены
по одному критерию — отношению нормализованных AND-наборов тегов:

| Значение `filterRelation` | Определение |
| --- | --- |
| `broader` | Набор тегов целевого узла — строгое подмножество исходного набора |
| `narrower` | Набор тегов целевого узла — строгое надмножество исходного набора |
| `same` | Наборы тегов целевого узла и исходного выбора совпадают |

Для `broader` снимается хотя бы один тег, новые не добавляются;
для `narrower` добавляется хотя бы один тег, прежние сохраняются.
Соотношение определяется фильтрами, не количеством элементов: даже
при одинаковых количествах фильтры могут быть шире или уже друг друга.

В согласованном наборе вариантов этим категориям соответствуют переход
к ближайшему более широкому пользовательскому узлу, уточнение по правилам
режима и явный вход из «Всё» в сохранённую подборку с пустым фильтром.
Последний — частный случай `same`: фильтр не меняется, выбранное положение
меняется. Идентичность подборки передаётся в сведениях о целевом узле, не кодируется
значением `same`. Пустой фильтр не означает отсутствие элементов.

Это классификация уже выдаваемых DAG-вариантов, не разрешение новых
переходов только по отношению фильтров. Правила ближайших узлов и режимов
сохраняются. «Назад», отдельное действие «Всё» и переходы между страницами
не добавляются в список; произвольная замена одних тегов другими также
не становится четвёртой категорией DAG-вариантов.
Имя `filterRelation` заменяет предложенное общее `role`; старый частный код
`empty_collection_entry` не сохраняется в принятом составе.
Имя поля и три значения приняты; физическая форма кодирования не выбрана.

Остальные [сведения о варианте](dag-navigator-upper-interface.DRAFT.md#сведения-о-варианте)
сохраняются: целевой узел, сведения для отображения, количество его элементов
и связь с исходным выбором. Приложение передаёт выбранный вариант обратно
Навигатору целиком. Оно не собирает цель из ID или показанной разницы тегов;
имена и точная структура остальных полей уточняются отдельно.

Соотношение передаётся в каждом варианте, поэтому отдельный вариант не теряет
эти сведения при передаче обработчику или общему элементу отображения.
Разные категории могут показываться в разных областях UI: потребитель
группирует готовые варианты по `filterRelation`, не вычисляет отношения
между фильтрами. Единый список
не задаёт визуальный порядок, сортировку или обязательную общую область UI.

Рассмотренная альтернатива — отдельные списки по категориям без поля в вариантах.
Она непосредственно соответствует раздельным областям UI и не повторяет
категорию у каждого варианта. Принят единый список; компромисс — повторение
соотношения в данных и группировка потребителем при раздельном отображении.
Это не утверждение об измеренном выигрыше памяти или времени.

Гарантия полного логического набора, сохранение переходов к подборкам
с нулевым количеством и проверка применимости по исходному выбору остаются
прежними. Способ внутренней связи с выбором и политика порядка этим
решением не выбираются. История и переходы между страницами в список
DAG-вариантов не включаются.

## Целевой узел и количество в варианте перехода

**Принято 2026-10-10 с термином «целевой узел».** `target` описывает
целевой узел теми же сведениями, что текущий выбор в `position`, а количество
его элементов передаётся рядом в `total`. «Узел» — общее понятие для
подборки и промежуточного узла; подборка является частным случаем узла,
а не противопоставляется ему. Определения закреплены в
[словаре концепта](../../concepts/selection-hierarchy/CONTEXT.md#навигация-через-облака-тегов).

| Поле варианта | Содержание |
| --- | --- |
| `target.filter` | Полный нормализованный AND-набор тегов целевого узла |
| `target.selection` | ID и название подборки, если целевой узел является подборкой в данном комплекте |
| `total` | Число уникальных элементов, соответствующих `target.filter`, согласованное с данным комплектом |

Внутри `target.selection` используются уже принятые `id` и `name`.
В готовом варианте отсутствие `selection` означает отсутствие соответствия
сохранённой подборке, а не ожидание дополнительных сведений. Промежуточному
узлу искусственный ID не нужен; режим `free` сам по себе не исключает
соответствия подборке. Общая форма описания целевого узла не добавляет
«Всё» или новые категории переходов в список.

Приняты группировка и имена двух полей; техническое имя `target` сохраняется.
Смысл полного фильтра, идентичности подборки, количества и выбора выданного
варианта не меняется.
Сведения для отображения и связь с исходным выбором остаются в варианте
по прежним правилам; их точная форма этим шагом не выбирается.
Потребитель передаёт обратно весь выданный вариант, не только `target`.

Например, для исходного `{фильм}` может быть показано «спокойное (3)»:
`target.filter = {фильм, спокойное}`, `target.selection` содержит ID
и название «Спокойные фильмы», `total = 3`. В подписи достаточно добавляемого
тега, но он не заменяет полного описания целевого узла. Если целевой узел
промежуточный, `selection` отсутствует; фильтр и количество остаются.

При последующем изменении фильтра непустой подборки переход сохраняет
показанные теги целевого узла, а новый комплект заново определяет соответствие
подборке и количество. Он не открывает новый фильтр только по прежнему ID.
`total` относится к показанному комплекту: после перехода значение может
измениться. Для явного входа в подборку с пустым фильтром сохраняются
[принятые проверки целевого узла](dag-navigator-upper-interface.DRAFT.md#изменившаяся-пустая-именованная-подборка).
Одинаковая форма `target` и `position` не обещает, что будущий текущий выбор
побайтно повторит сведения старого варианта.

Рассмотренная альтернатива — разные описания целевого узла: только ID для
подборки и только теги для промежуточного узла. Первый случай не сохраняет
показанный фильтр при изменении подборки; пришлось бы хранить его отдельно
или вводить дополнительное определение целевого узла. Принят общий
`target` с фильтром и необязательной подборкой. Компромисс — полный набор
тегов передаётся и для сохранённых узлов. Это логическая полнота,
не требование физически дублировать все значения при передаче.

Сведения о подборке сохраняют её идентичность, но не обещают готовность
индекса. [Возможность целевой оптимизации](dag-navigator-data-access.DRAFT.md#возможность-оптимизации-сохранённых-подборок)
учитывается без новых команд или обязательных сведений о способе вычисления.
Схема не выбирает язык, JSON, способ хранения ссылок или размещение по стеку.

## Изменение фильтра в варианте перехода

**Принято 2026-10-10 после уточнения формы и симметрии UI.** Вариант
передаёт один набор `changedFilterTags`: ссылки на все теги, чьё присутствие
в фильтре изменится при выборе этого варианта. Сами определения тегов,
их названия и разметка элементов при этом не редактируются.
Для исходного фильтра `Q` и фильтра целевого узла `T`:

| `filterRelation` | Состав `changedFilterTags` | Смысл изменения |
| --- | --- | --- |
| `narrower` | Теги из `T`, которых нет в `Q`; набор непуст | Добавить эти теги в фильтр |
| `broader` | Теги из `Q`, которых нет в `T`; набор непуст | Снять эти теги с фильтра |
| `same` | Пустой набор | Фильтр не меняется |

Имя `changedFilterTags` и использование `filterRelation` вместо отдельного
булева признака приняты. Прежние `displayTags` и `filterChange { added,
removed }` не входят в выбранную схему. Два набора были допустимы, но один
из них всегда пуст для нынешних уточнений и расширений; один набор требует
читать его вместе с уже имеющимся `filterRelation` и не дублирует направление.

Это полный набор изменяемых тегов, не ограниченный местом на экране.
Снятие убирает требование из фильтра, не удаляет тег и не означает `NOT`.
Правило не вводит вариантов, одновременно добавляющих и снимающих теги.
Произвольное задание фильтра остаётся другой формой действия выбора,
а не новой категорией выдаваемых DAG-переходов.
При `same` пустая разница не означает `no_action`: явный вход из «Всё»
в именованную подборку с пустым фильтром меняет выбранный узел.
При расширении к пустому фильтру `changedFilterTags` содержит весь `Q`.

**Принято для UI:** в обоих направлениях показывается изменение фильтра:
`+спокойное` для добавления, `−спокойное` для снятия. Показ снимаемых тегов
не является только факультативным дополнением к расширению. Полный фильтр
или название целевого узла можно показывать дополнительно, симметрично
для обоих направлений. Расположение, размер, порядок и разделители тегов
не фиксируются; оформление остаётся вне предметных правил DAG.
При `same` нет добавляемых или снимаемых тегов, поэтому знак изменения
не придумывается; сведения о целевом узле сохраняются.
Код прототипа пока не приведён к этому правилу: принято решение для UI,
не заявлено выполненное визуальное изменение.

Нужные отображаемые названия доступны в том же целостном комплекте
по [принятому правилу](dag-navigator-data-access.DRAFT.md#получение-отображаемых-названий-тегов).
Приложение не догружает их и не вычисляет разницу самостоятельно.
Согласованность производного набора с фильтрами обеспечивает составной
интерфейс. Для исполнения передаётся весь выданный вариант; полный фильтр
не восстанавливается приложением из `changedFilterTags`.

### Сводка состава варианта перехода

Все четыре читаемых поля ниже приняты:

| Поле | Содержание |
| --- | --- |
| `filterRelation` | Соотношение фильтра целевого узла с исходным |
| `target` | Полный фильтр целевого узла и сведения о подборке, если она есть |
| `total` | Число элементов целевого узла в данном комплекте |
| `changedFilterTags` | Полный набор тегов, добавляемых или снимаемых в соответствии с `filterRelation` |

Связь с исходным выбором остаётся служебной частью выданного варианта
по [принятому правилу](dag-navigator-upper-interface.DRAFT.md#связь-варианта-с-навигационным-выбором).
Эта сводка не разрешает пересобрать вариант только из четырёх читаемых
полей, потеряв его служебную связь. Приложение передаёт вариант целиком;
проверка связи остаётся внутри Навигатора. Физическая форма связи открыта:
новая публичная метка, серверная сессия, способ сериализации или привязка
к адресу объекта в памяти здесь не выбираются.

## Доступность отображаемых названий

**Принято 2026-10-10:** [гарантия доступа к названиям](dag-navigator-data-access.DRAFT.md#получение-отображаемых-названий-тегов)
отделена от формы их представления. Способ обеспечения доступности
определяется реализацией; копирование названий в каждый результат не требуется.
Предложение поля `result.tagNames` снято как преждевременное, ранее принятая
группировка результата сохраняется.

Гарантия охватывает названия тегов текущего фильтра, целевых фильтров
и `changedFilterTags`. Если согласованный состав элемента выдачи включает
ссылки на отображаемые теги, для них действует та же гарантия; новых полей
элемента это не вводит. Названия подборок остаются в `selection.name`.

Форма связи названий с результатом остаётся открытой. Отображение названий
и устройство глоссария относятся к общим возможностям, не к правилам DAG.

## Комплект и текущее состояние — разные сведения

Это следствия уже принятых правил, не новая политика:

| Сведения | Где доступны |
| --- | --- |
| Полученные согласованные данные | В `result` успешного обращения и в доступном комплекте единого состояния, пока состояние ему соответствует |
| Новая запрошенная цель, режим и параметры выдачи | В текущем состоянии, даже если их комплект ещё не получен |
| Ход выполнения, отставание и ошибки актуализации | В текущем состоянии; не меняют задним числом старый `result` |
| Доступность действий сейчас, включая фактический «Назад» | В текущем состоянии; условия заново проверяются при вызове |
| Сведения для сохранения/восстановления сеанса | В соответствующем взаимодействии с сеансом; полный маршрут не добавляется в каждый комплект |

Доступность действий нельзя получать из сохранённого результата старой
операции как разрешение на действие сейчас. Сами готовые варианты перехода
в `result` остаются, но их применимость проверяет Навигатор по действующему
выбору и режиму. Обычное приложение не сопоставляет частичные ответы.

Отсутствие готового комплекта отличается от полученного `total = 0`
и пустой выдачи. Для `failed`, `rejected`, `superseded`, `cancelled` и `no_action`
успешного `result` нет. Прежний комплект той же выборки при неудаче
актуализации доступен через состояние, но не становится результатом ошибки.

Ревизия источника, основания учёта изменений и идентификатор попытки нужны
внутренней проверке. Эта схема не добавляет их как обязательные поля
обычного результата. Метка не заменяет такую проверку и не обещает
бессрочной свежести. Необязательная диагностика определяется отдельно.

## Покрытие потребностей приложения

Проверка схемы как целого, 2026-10-08, дополнена 2026-10-09.
Это сопоставление с согласованными сценариями, не тест реализации;
группировка принята отдельным ответом пользователя.

| Потребность | Основание в схеме или текущем состоянии |
| --- | --- |
| Показать текущую выборку, её теги и имя сохранённой подборки | `dag-navigation.position` |
| Различить пользовательские узлы и свободный режим | `dag-navigation.mode` |
| Показать родителей, уточнения и явный вход в пустую именованную подборку | `dag-navigation.transitions`, роли вариантов и отображаемые названия |
| Выполнить выбранный показанный переход, не вычисляя его цель в приложении | Выданный вариант со своей целью и связью с исходным выбором |
| Показать общее количество и количества элементов целевых узлов | `results.total` и `total` отдельных вариантов перехода соответственно |
| Показать элементы полученной страницы и понять её параметры | `results.items` и `results.view`; конкретные поля элементов и форма места ещё открыты |
| Отличить новый применённый комплект от изменения статуса обновления | `bundleId` и ход актуализации в текущем состоянии |
| Показать доступность «Назад» и других действий, ожидание или ошибку | Единое текущее состояние, не сохранённый `result` |

Общее количество хранится в составном результате один раз.
Это расположение публичных сведений, а не требование DAG-модулю зависеть
от конкретной реализации выдачи или самостоятельно читать её внутреннее
состояние. Распределение вычислений и получение количества через источник
остаются отдельными вопросами.

Проверка скрытых требований:

- `bundleId` не требует серверной сессии, глобального счётчика или журнала
  всех когда-либо выданных комплектов.
- `items` ограничен запрошенной страницей; все элементы выборки не требуются.
- `view` не вводит обязательный номер страницы, переход к произвольному
  номеру или фиксированный размер. Параметры и доступность действий выдачи
  уточняются в её общем контракте.
- Полный логический набор `transitions` и точные количества сохраняют
  ранее согласованные требования, не новую гарантию дешёвого получения.
  Уже выявленные ресурсные риски не снимаются компактностью схемы.
- Неизвестная выдача не представляется пустыми `items` с нулём; готового
  комплекта в этом случае ещё нет. Готовый нулевой результат допустим.

Дополнительных верхних блоков по этой сверке не требуется. Общая группировка
и приведённые имена полей приняты. Логические поля `position` и варианта
перехода приняты в соответствующих разделах выше; их физические типы
и служебная связь перехода ещё не выбраны. Данные элемента зависят
от применения, а точные поля `view` остаются отдельным предложением
в общем контракте выдачи.

## Документальная сверка

| Сценарий | Что должна сохранять схема |
| --- | --- |
| Успешно получена выборка без элементов | Есть полноценный комплект, `total = 0`, `items` пуст; переходы к подборкам с нулевым количеством не скрываются автоматически |
| Свободный набор не совпал с подборкой | Есть теги, режим, варианты и выдача; искусственный ID подборки не нужен |
| Открыта пустая именованная подборка | Отличается от «Всё» в `position`, даже при одинаковом составе элементов |
| Один элемент заменён другим, общее количество не изменилось | Новый согласованно применённый комплект имеет новую метку и соответствующую страницу |
| A завершилась, затем начата B | `result` A не изменяется; текущее намерение и доступность действий относятся к B |
| Фоновое обновление той же выборки завершилось ошибкой | Состояние сохраняет прежний комплект и сообщает ошибку; нового успешного `result` не возникает |
| Источник установил недоступность фильтра из-за тега | Нет нового успешного `result`, выбранные теги сохраняются в состоянии; недоступность не изображается как `total = 0` |
| Во время подготовки ручного ввода пользователь редактирует текст | Черновик и отправленный ввод относятся к общему вводу, не добавляются в неизменяемый результат навигации |
| Экземпляр завершён во время получения | Отменённое обращение не получает успешного `result`; ранее выданные значения не меняются |

Сверка дополнена 2026-10-09 по принятым решениям о названиях, ручном вводе,
недоступном фильтре и завершении экземпляра. Верхних блоков для них
добавлять не требуется; её группировка принята отдельным решением.

Сверка логическая, не тест реализации. Схема не добавляет новую политику
пагинации, истории, актуализации или публичного ручного управления частями.
Сведения о текущем выборе, единый список вариантов с `filterRelation`,
целевой узел в `target` и его количество элементов в `total` приняты;
физические типы и остальные вложенные структуры остаются открытыми.
