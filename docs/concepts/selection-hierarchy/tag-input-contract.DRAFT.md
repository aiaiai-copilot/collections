# Ручной ввод тегов

Родитель: [Навигация и получение результатов](../../product/navigation-and-results.md).
Связь: общий механизм — определяет преобразование и применение ручного ввода тегов.

Статус: **логические правила преобразования, ответа,
применения целого пакета и отделения черновика приняты**. Физические
форматы и некоторые политики модели данных ещё открыты; реализации нет.

## Роль и границы

Этот документ выделяет уже согласованную логику ввода, не специфичную
для DAG: преобразование названий в ссылки на теги, подготовку целого
пакета, его связь с явным действием пользователя и редактируемым черновиком.

[Настроенный доступ](dag-navigator-data-access.DRAFT.md) обеспечивает
преобразование по модели тегов конкретного применения. Разбор текста
и состояние поля относятся к логике ввода. Изменение текущего фильтра
в данном применении выполняется [обычной командой Навигатора](dag-navigator-actions.DRAFT.md#dag-действия).
Правила родителей, уточнений, истории и страниц сюда не переносятся.

Выделение логической обязанности не требует отдельного публичного
метода, пакета, класса, frontend/backend-разделения или сервиса.
Использующий код приложения не получает обязанность вручную собирать
части навигационного результата. Документ также не определяет операции
создания, переименования или удаления записей глоссария.

## Согласованные правила

### Преобразование введённых названий в ссылки

Для ручного ввода нужна обратная
задача: получить значения `TagRef`, соответствующие введённым названиям.
Это преобразование выполняется через настроенный доступ к данным,
согласно модели тегов конкретного применения. Обычному приложению не нужно
самостоятельно реализовывать правила сопоставления названий с тегами.

Это не новая обязанность предметных правил DAG. Разбор текста поля на
отдельные введённые названия относится к вводу; сопоставление с тегами —
к модели тегов и её адаптеру; применение подготовленного набора к фильтру —
к уже принятым навигационным командам. Разделение логическое: три отдельных
класса, процесса, сервиса или публичных метода не требуются.

Название сопоставляется со ссылкой на запись глоссария. Одинаковый текст не позволяет подменять сохранённую ссылку другим тегом. Ввод нового названия и восстановление ссылки — разные задачи. Преобразование не создаёт запись глоссария и не меняет фильтр; изменение происходит после явного применения ввода.

Физическая форма сообщения о неразрешённых названиях требует определения. Для полученной ссылки действует [правило недоступного фильтра](dag-navigator-data-access.DRAFT.md#фильтр-с-недоступным-тегом). Ввод применяется целым пакетом.

### Применение только полностью разрешённого ввода

Ручной ввод применяется к фильтру одним пакетом, только когда
для всех введённых названий
получены однозначные допустимые значения тегов. Если часть названий
преобразовать нельзя или требуется уточнение, распознанная часть отдельно
не применяется. Черновик ввода сохраняется; пользователь получает сведения,
какие названия требуют исправления или выбора. Редактирование черновика
не меняет действующий фильтр и историю.

Это правило подготовки команды ввода, а не обхода DAG или редактирования
глоссария. Принятое отклонение пакета с неправильной формой аргументов
сохраняется; оно само по себе не определяло поведение неразрешённых названий.
Неразрешённое название не объявляется автоматически `invalid_arguments`
навигационной команды: готовая команда с набором ссылок ещё не сформирована.

Возможность получить допустимый тег определяется моделью данных:

- Если название отсутствует в глоссарии, ввод не создаёт тег автоматически: требуется исправление либо отдельное явное создание записи.
- Отсутствие подходящих элементов не препятствует выбору существующего тега и получению пустой выборки.
- Сбой получения отличается от установленной невозможности преобразовать название.

Например, если для `фильм нет_такого_тега` модель допускает оба значения,
применяется весь пакет. Если второе название не удалось однозначно разрешить,
не применяется ни один из двух тегов; текущий фильтр остаётся прежним.

Здесь не выбираются коды ответа преобразования, внешний вид сообщения,
политика совпадений нескольких записей, правила удаления тегов или механизм
создания записей глоссария. Не вводится автоматическая очередь применения
черновиков; ожидание подтверждения пользователя и техническое получение
данных — разные состояния. Независимая актуализация текущего результата
продолжает действовать по прежним правилам.

#### Документальная сверка применения ввода

| Случай | Следствие принятого правила |
| --- | --- |
| Все названия преобразованы в допустимые однозначные ссылки | Подготовлен целый пакет для обычной навигационной команды; её собственные предусловия сохраняются |
| Для части названий нет допустимой ссылки либо требуется выбор | Распознанная часть не применяется; черновик и действующий фильтр сохраняются |
| Модель допускает тег, но подходящих элементов нет | Нулевое количество не препятствует применению; это не ошибка преобразования |
| Получение сведений завершилось сбоем | Частичный пакет не применяется; ошибка не объявляется отсутствием тега |

Сверка не добавляет новых исходов навигационной команды и не утверждает
физическую форму ответа преобразования. Термин «автодополнение» в это
правило не вводится; прежние подсказки при вводе не определяют допустимость
пакета и не являются условием его применения.

### Состав ответа преобразования

Возможность преобразования
используется для всего переданного пакета названий. Ответ
предоставляет либо готовый пакет ссылок, либо сведения, необходимые
для исправления ввода. Технический сбой различается с проблемой названий.
Это логическая форма ответа возможности доступа, не новые итоги или причины
навигационных команд и не состояние DAG.

| Вариант ответа по смыслу | Необходимое содержание |
| --- | --- |
| Весь ввод преобразован | Полный пакет допустимых однозначных `TagRef`, пригодный для передачи обычной команде изменения фильтра |
| Ввод требует исправления или уточнения | Перечень неразрешённых названий с привязкой к исходному вводу и установленной причиной для каждого; готовый к применению пакет не выдаётся |
| Преобразование завершилось техническим сбоем | Различимый сбой выполнения, не утверждение о недопустимости введённых названий; подробности диагностики остаются необязательными |

Связь с исходным вводом нужна, чтобы указать пользователю конкретное
проблемное название. Она может обеспечиваться положением в переданном
пакете или иным согласованным способом; повтор всего текста, символьные
координаты, отдельный ID каждого слова и ID экземпляра Навигатора
обязательными не становятся. Причина должна быть различима программно,
не только по свободному тексту сообщения; её коды и точный состав пока
не выбираются. Примеры причин — отсутствие допустимого тега для названия
в данной модели или невозможность однозначного сопоставления. Эти примеры
не вводят обязательную поддержку одноимённых тегов в каждой модели.

Перечень проблем в завершённом ответе о вводе охватывает все неразрешённые
названия переданного пакета. Если получение не удалось завершить,
отсутствие проверки остальных названий не выдаётся за установленный
исчерпывающий перечень проблем ввода. Обязательного автоматического выбора
из кандидатов или загрузки всего глоссария это не требует.

Успешное преобразование ещё не означает успешную навигацию: выбор,
история и результаты меняются только по принятой навигационной команде
с её собственными предусловиями и итогом. При проблеме ввода не требуется
выдавать частичные успешные ссылки обычному потребителю; допустимость
внутреннего переиспользования результатов не запрещается. При техническом
сбое пакет также не применяется; сохраняется различие технического повтора
и исправления пользователем самого ввода.

#### Документальная сверка ответа преобразования

Сверка последствий принятого состава, не дополнительные решения:

- При готовом пакете потребитель не собирает успешные ответы по отдельным
  названиям; применение выполняется обычной командой фильтра.
- Ответ о проблемах ввода позволяет указать все неразрешённые названия
  конкретного переданного пакета. Для готовности не требуется отдельный
  дублирующий флаг: она различается самим вариантом ответа.
- Технический сбой не превращается в список «неизвестных тегов» и не
  означает нулевую выдачу. Диагностические подробности не становятся
  обязательным содержанием сообщения пользователю.
- Ни один ответ преобразования сам не изменяет выбранные теги, историю
  или глоссарий. Успешное преобразование не заменяет проверок и итогов
  последующей навигационной команды.

Формат ответа этой сверкой не определяется; недоступные ссылки
подчиняются общему правилу фильтра, указанному выше.
Связь с изменениями во время подготовки рассмотрена ниже.

### Изменения во время подготовки ввода: следствия принятых правил

Таблица описывает взаимодействие подготовки ввода с изменениями данных и навигацией.

| Изменение | Что уже определено |
| --- | --- |
| После получения ссылки тег переименован | Ссылка продолжает обозначать тот же тег; повторно выбирать его по старому отображаемому названию не требуется |
| После получения ссылки прежний тег удалён, создан другой с тем же названием | Ссылка не подменяется ссылкой на новый тег. Если источник установил невозможность обслужить фильтр со старой ссылкой, действует общее правило недоступного фильтра |
| Фоново изменились элементы или сведения о записи пользовательского среза при прежнем выбранном наборе | Само обновление не меняет выбранные теги. Прежние количества нельзя считать ответом новой команды; она получает свой согласованный результат |
| Пользователь перешёл к другой выборке до применения подготовленного добавления | Добавление, задуманное относительно прежней выборки, не переносится незаметно на новую; поздняя подготовка не должна увести пользователя обратно |
| К моменту вызова относительной команды её целостная основа не готова | Сохраняется принятый отказ в преждевременном зависимом действии; готовые ссылки не разрешают скрытую очередь команд |

Основания: [идентичность и отображаемое название](dag-navigator-upper-interface.DRAFT.md#идентичность-тега-и-отображаемое-название),
[устойчивость ссылки](dag-navigator-upper-interface.DRAFT.md#устойчивость-tagref-в-одной-области-данных),
[устойчивость выбранного набора](dag-navigator-contract.DRAFT.md#3-состояние-и-идентичность),
[правила применимости действий и ответов](dag-navigator-behavior-model.DRAFT.md#3-инварианты),
[преждевременное зависимое действие](dag-navigator-upper-interface.DRAFT.md#преждевременное-зависимое-действие).

Стыковка относится к логике подготовки и исполнения пользовательского
действия, а не к поиску родителей DAG. Адаптер преобразования не обязан
знать текущий черновик, историю или экземпляр Навигатора. Связь ответа
с конкретным обращением не означает, что источник принимает решения
за UI о применении результата. Смена ревизии сама по себе не меняет
смысл `TagRef`; пожизненная доступность тега этим не обещается.

Редактирование поля и ранее начатое явное применение различены
следующим принятым правилом.

### Отправленный ввод и редактируемый черновик

После явного применения ввода
отправленный пакет названий фиксируется для этого обращения. Последующее
редактирование поля создаёт другой черновик, но само по себе не отменяет
уже отправленное применение. Его результат относится к
отправленному пакету, не к новым буквам в поле.

Завершение прежнего обращения не должно очищать или перезаписывать более
новый черновик. Проблемы прежнего пакета не представляются как результат
проверки нового текста. Способ показа завершившегося обращения и нового
черновика здесь не выбирается; различать их нужно логически.

Если пользователь явно применяет новый ввод, пока прежний ещё только
преобразуется и не передан навигационной команде, новый запрос заменяет
прежнюю подготовку к применению. Поздний ответ прежней подготовки сам
команду не запускает. Это не означает обязательную физическую остановку
или запрет переиспользовать пригодные результаты преобразования.

Если прежняя навигационная команда уже принята, её нельзя считать
невыполненной или откатить этим правилом. Последующее действие проходит
обычные проверки доступности и принятые правила навигационных обращений.
Запрет переноса добавления на другую выборку из сверки выше сохраняется;
редактирование черновика и переход к другой выборке — разные события.

Пример: пользователь применил `спокойное`, а пока идёт преобразование,
начал вводить `вечер`. По принятому правилу применяется отправленное
`спокойное`; `вечер` остаётся неподанным черновиком и не исчезает при
завершении. Если до передачи команды пользователь явно применил `вечер`,
он заменяет прежнее ожидающее применение, а не создаёт очередь из двух.

## Сквозная документальная сверка

Сверка применяет принятые правила; новых политик, кодов ответа
и требований к физической организации не добавляет.

| Последовательность | Результат по принятой модели |
| --- | --- |
| Отправлен ввод, все названия разрешены, исходная выборка подходит | Подготовлен один целый пакет для обычной команды; успех преобразования не заменяет её итог |
| После отправления пользователь редактирует поле | Прежнее применение продолжает относиться к отправленному пакету; новый черновик не применяется и не очищается его завершением |
| До передачи прежнего пакета команде явно применён другой ввод | Новый запрос заменяет прежнюю подготовку; поздний ответ прежней сам команду не запускает |
| После принятия команды пользователь применяет следующий ввод | Действуют обычные предусловия и итоги навигационных команд; прежняя команда не откатывается правилом черновика |
| До передачи пакета команде пользователь ушёл к другой выборке | Подготовленное добавление не переносится на новый выбор и не возвращает пользователя к прежнему |
| При прежнем выборе фоново обновились данные | Выбранные теги сохраняются; результат команды получают по её условиям, старые количества не подставляются |
| После получения ссылки изменилось название того же тега | Смысл ссылки сохраняется; она не превращается в новый поиск по старому названию |
| Во время подготовки использование экземпляра завершено | Поздняя подготовка не возобновляет экземпляр; новые команды после завершения не обслуживаются по общему правилу |

Последняя строка опирается на [окончательное завершение экземпляра](coherent-result-contract.DRAFT.md#окончательное-завершение-экземпляра)
и [обращения после завершения](coherent-result-contract.DRAFT.md#обращения-к-завершённому-экземпляру).
Она не добавляет к трём ответам преобразования новый публичный код
и не обещает мгновенную остановку удалённого вычисления.

## Оставшиеся решения

- Физическое представление `TagRef`, пакета названий, привязки проблем
  к вводу и кодов причин.
- Конкретные правила сопоставления названий и выбора при неоднозначности
  в управляемой модели тегов.
- Отображение недоступных ранее полученных ссылок и конкретная политика
  удаления/объединения тегов. Сохранение выбора и сообщение о недоступности
  уже приняты на общем уровне фильтра, не в преобразовании текста.
- Конкретное представление состояния ввода и его связи с применением,
  не требующее от UI интерпретировать внутренние стадии получения данных.

Настоящая сверка не объявляет интерфейс полностью специфицированным.
